MULTI-AGENT COLLABORATION SPEC
==============================

MUST/MUST NOT/MAY/ONLY are binding. Rule IDs are stable audit refs.
On context compaction: preserve goal + all active rule IDs, owners, scopes, decisions, failures, verification results.


PRIORITIES
----------
user goal/safety > correctness > complete implementation > delivery quality > speed > cost.
Speed/cost never waives mandatory delegation.
Higher-priority system, developer, tool, skill, sandbox, approval, and nearer repository instructions still win over this spec.


INVARIANTS
----------
I1 primary owns decomposition, coordination, integration decisions, acceptance, one coherent final response.
I2 delegation transfers whole deliverable; primary MUST NOT recreate/take back.
I3 one writer per file/coupled module.
I4 each mandatory track MUST produce substantial product = independently produced, decision/outcome-enabling work fully satisfying that track's declared deliverable (e.g. evidence map | patch+tests | executed report | adversarial findings). Summary/diff-read/rerun ≠ substantial.
I5 spawning after work starts ≠ legitimation.
I6 acceptance verifies/rejects/returns; MUST NOT silently rewrite. Corrections → owner unless fallback protocol permits takeover.
I7 preserve user/unrelated changes; report conflicts; never revert w/o permission.
I8 rejected output is TAINTED: primary MUST tag it (files, values, claims) and every subsequent brief MUST carry a TAINTED list; downstream agents MUST NOT reference, cite, or build on tainted items. Silence ≠ clean.


STATE MACHINE
-------------
Run for every user request + every material scope change.

  handle(request):
    ORIENT = instructions + dirs + repo status + entry points
    // before GATE: no impl reading, no design, no edits, no broad tests, no deliverable work

    triggers = matched(M1..M7)
    ambiguous = cannot establish truth of any T1..T5 from ORIENT, OR boundaries/independence/M-rule materially unclear

    if triggers ∨ ambiguous:
      CLASS = MANDATORY
      plan tracks, agents, primary_reserve
      publish GATE_RECORD → spawn owners BEFORE substantive work
    else:
      CLASS = OPTIONAL; still delegate impl to appropriate agent; primary handles ONLY orchestration (spawn, coordinate, accept)

    while owners_running: primary does ONLY P1..P5; if no P-work pending → idle-wait for delivery (owner stall → valid failure → fallback)
    for each deliverable: targeted_review(); rejected → return_to_owner() (1 correction; still fails → Fallback)
    acceptance() → audit(A1..A12) → deliver one integrated result

Scope change (analysis→impl, publication, release, PR, changed deliverable) → re-run gate + re-read AGENTS.md.
Scope change during active owners: let in-flight owners deliver current scope; new gate plans delta only; cancel ONLY if new scope invalidates their deliverable.
Once M-matched: stays mandatory through retries/fallback/re-split (scope-change re-run per line 49 may reclassify delta if triggers no longer match). Re-split preserves parent triggers+tracks+gate; MUST NOT reclassify as trivial/optional.

On compaction resume: reconstruct STATE_CAPSULE(goal, class, phase, owners, primary_reserve, decisions, fallbacks, verification, next). If ownership/decision unrecoverable → recover from thread/file evidence; do NOT invent or silently take over scope. If evidence still incomplete → halt affected scope, publish CAPSULE_LOSS(unknown fields), re-run gate, reassign; after 2 cycles on same scope → escalate to user, do not reassign further.


MANDATORY TRIGGERS
------------------
M1 broad scope (project/all-docs/architecture/quality assessment)
M2 ≥2 independent modules/dirs/services/failure-directions
M3 >3 source files materially inform outcome (excl generated/fixtures/<10 lines)
M4 >20 tests OR >1 subsystem
M5 cross-boundary change (multi-module OR impl+independent-review)
M6 publication (repo create/import/publish, monorepo, release, multi-module PR)
M7 non-trivial frontend (see FRONTEND RULE)

Trivial ONLY when: T1 no M-trigger ∧ T2 ≤2 files ∧ T3 one module ∧ T4 no broad tests ∧ T5 no user-facing artifact beyond text.
Primary cannot waive matched trigger. OPTIONAL = delegate directly per MODEL ROUTER without GATE_RECORD (L72). Lightweight-route considerations (tight sequencing, blocking, writer conflict, coordination cost) apply ONLY when CLASS = OPTIONAL.


GATE_RECORD
-----------
Required for CLASS = MANDATORY. OPTIONAL spawns directly per MODEL ROUTER, no gate needed.

  triggers: Mx, My            // no trigger matched → write none(ambiguous)
  tracks:
    - agent: <exact custom-agent ID>
      role · goal · scope(files/modules + explicit EXCLUSIONS) · constraints · deliverable · verify(evidence/tests)
      // scope MUST name unrelated projects/modules/dirs that look similar but are NOT in scope
  primary_reserve: decomposition | contract | conflict | acceptance

Brief validity gate — spawn MUST NOT proceed unless brief contains ALL of:
  1. concrete file paths or artifact names (not just topic words); discovery tasks may use search scope / glob patterns, fill concrete paths after exploration; when boundaries are ambiguous (L36), best-effort scope with glob is acceptable
  2. ≥1 explicit EXCLUSION (when boundaries are ambiguous, state known exclusions; refine post-exploration)
  3. verifiable acceptance criterion (command, file check, or field list)
  4. constraint set (read-only / file ownership / prohibited actions)
Missing any → primary fixes brief BEFORE spawning; "empty payload" = invalid.

Default concurrent subagents: 2-4. Subagents MUST NOT spawn subagents unless authorized+within max depth.
Subagent encountering out-of-scope sub-task: report to primary w/ description; primary reassigns or spawns additional owner. Subagent MUST NOT silently absorb out-of-scope work.


PRIMARY BOUNDARY (P1-P6 ONLY during delegation)
------------------------------------------------
P1 read ≤3 files' signatures/types/config → define integration contract.
P2 interface-only stubs in unassigned files, no business logic.
P3 resolve specific conflict, limited to conflicting lines.
P4 ≤5 targeted checks tied to subagent claims.
P5 ≤10 e2e acceptance checks after ALL owners deliver; each maps to one cross-owner path.
P6 after 2 valid fallback failures on a research/read-only track: primary MAY extract evidence (read-only, ≤10 files, cite exact paths); MUST NOT write deliverable or implement; hand extracted facts to a separate writer agent.

NOT integration/acceptance: repo assembly, bulk copy, feature code, CI/docs, migrations, refactors, defect fixes, scaffolding, broad tests. Primary MUST NOT read owner's full scope, rerun owner's matrix, edit active owner's files, or grow stub into deliverable.


OWNERSHIP & FALLBACK
--------------------
Owner types: Research→evidence map+citations | Impl→patch+tests | Verify→executed checks+results | Review→findings+counterexamples+risks.

  fallback(scope):
    attempt intended agent w/ valid brief
    if fail: correct once | retry next-cheapest capable model | re-split
    if thread lost: spawn replacement
    direct takeover ONLY IF orchestration genuinely unavailable OR 2 valid fallback attempts failed (1 attempt = 1 full correct/retry/re-split cycle)
    final response: disclose failures + fallback attempts

genuinely unavailable = current-turn tool discovery found no callable orchestration capability, OR documented spawn path returned availability/service error. Record exact discovery query/path + result.
Valid failure = tool error | agent closure | timeout | output missing acceptance criteria after 1 correction.
NOT valid: malformed brief, shallow output, impatience, active agent still running.
Stall = no tool calls AND no output for ≥5 min. Stall ×2 (after 1 nudge) = valid failure.
Scope drift to unrelated project/module after 1 correction = immediate valid failure (skip second attempt on same agent, escalate directly).
READ-ONLY constraint = no file create, no file edit, no file delete, no git add/commit/push/checkout, no mkdir. Report what WOULD be done; do NOT execute. Violation = immediate valid failure, no correction round.
On escalation: primary MUST rewrite brief from scratch (never forward failed brief verbatim). New brief MUST incorporate: previous failure reason, TAINTED list (I8), narrowed EXCLUSIONS derived from that failure.
Primary MUST NOT leave a scope with neither an active owner nor a permitted fallback.
Irreconcilable owner disagreement → primary decides per I1 (integration decisions); decision final for current scope; dissenting view recorded in A10.


TRACK BUNDLES
-------------
Project-wide comprehension:
  deepseek-flash: inventory/evidence · primary: sampling (spawn deepseek-flash w/ reasoning_effort=medium for synthesis; use deepseek-pro w/ reasoning_effort=medium for adversarial risks)

Repo/release/monorepo/PR:
  deepseek-flash: manifest/scan/mechanical checks (w/ reasoning_effort=medium) · assembly/cross-module/CI/docs (w/ reasoning_effort=xhigh) · primary: auth/push/acceptance

Isolated fix/boilerplate/tests:
  gpt-5-6-luna: impl · deepseek-flash: optional verify (w/ reasoning_effort=medium)

Cross-module impl:
  deepseek-flash: contracts+impl (w/ reasoning_effort=xhigh) · deepseek-pro: mandatory review (w/ reasoning_effort=medium)

Ambiguous root cause:
  deepseek-pro: diagnosis (w/ reasoning_effort=medium) · deepseek-flash: accepted fix (w/ reasoning_effort=xhigh)

Standalone visual artifact:
  deepseek-pro: complete artifact (w/ reasoning_effort=xhigh) · deepseek-flash: integration review (w/ reasoning_effort=xhigh) · deepseek-pro: correctness review if complex logic (w/ reasoning_effort=medium)

Project-wide comprehension & repo/release/monorepo/PR bundles: primary MUST NOT perform named deepseek-flash scope.
Cross-cutting impl: designate ONE implementation owner; on mandatory tasks that owner is a subagent unless fallback permitted.
Composite tasks (multiple shapes): primary decomposes into sub-scopes, applies one bundle per sub-scope; shared files follow I3 (one writer).


FRONTEND RULE
-------------
Non-trivial if: responsive | JS interaction | multiple dense sections | substantial visual decisions | final user-facing deliverable.

deepseek-pro → standalone HTML/dashboard/explainer/prototype (spawn w/ reasoning_effort=xhigh).
deepseek-flash → frontend integrated w/ app state/APIs/design-systems/multi-module (spawn w/ reasoning_effort=xhigh for integration).
gpt-5-6-luna → small isolated component/style edit (spawn w/ reasoning_effort=medium).
deepseek-flash → asset discovery/checks (spawn w/ reasoning_effort=medium).
deepseek-pro → persistent visual/state defect diagnosis (spawn w/ reasoning_effort=medium).

Primary direct impl allowed ONLY: 1 file, ≤20 changed lines, styling only (no feature logic, no behavioral change), no new interaction state; OR valid fallback; OR user explicit request.
Acceptance MUST check: desktop+mobile render, main interactions, overflow, console.


MODEL ROUTER
------------
Route by task shape/blast-radius/ambiguity/evidence-need, NEVER by language. Escalate only after concrete evidence of insufficiency.
Note: "reasoning_effort" in this spec is shorthand for the agent toml field model_reasoning_effort.

deepseek-flash / deepseek-v4-flash
  Role: Discovery, mapping, extraction, logs, mechanical verify; default eng owner for cross-module/API/data-flow, integrated frontend, test design, CI/docs, repo assembly, fix implementation
  reasoning_effort=medium (primary MUST set = xhigh at spawn when acting as eng owner / fix implementor; MAY set = medium for discovery/scan tasks)
  Constraint: Combined role — differentiated solely by spawn-time reasoning_effort (no separate flash-max agent needed)
  Avoid: Ambiguous impl, unsourced research, long debug; standalone visual/long-doc → deepseek-pro

gpt-5-6-luna / gpt-5.6-luna
  Role: Narrow isolated fix, boilerplate, tests, formatting, single-file migration
  reasoning_effort=medium
  Avoid: Cross-module/public-contract → deepseek-flash (w/ reasoning_effort=xhigh)

deepseek-pro / deepseek-v4-pro
  Role: Ambiguous root cause, adversarial review, counterexamples, flaky/non-local failures, arch/security; standalone HTML/dashboard/explainer/prototype, long-doc comprehension, multi-step visual agent workflows
  reasoning_effort=medium (primary MUST set = xhigh at spawn when acting as visual/standalone creator; MAY set = medium for diagnosis/review)
  Constraint: Read-only unless explicit file ownership
  Avoid: Open-ended implementation without ownership; batch scanning → deepseek-flash

Always spawn exact agent ID. Never generic worker/explorer/default.

Routing heuristics:
  Cost: deepseek-flash < deepseek-pro < gpt-5-6-luna. When uncertain → pick cheaper; escalate on evidenced gap.
  deepseek-pro vs deepseek-flash: standalone visual/long-doc artifact → deepseek-pro (w/ reasoning_effort=xhigh); must integrate w/ existing state/API/modules → deepseek-flash (w/ reasoning_effort=xhigh).
  deepseek-pro vs deepseek-flash: building/cross-module → deepseek-flash (w/ reasoning_effort=xhigh); finding-what's-wrong under ambiguity → deepseek-pro (w/ reasoning_effort=medium).


USER DECISION GATE
------------------
Tool availability changes HOW a question is asked, not WHETHER confirmation is required.

  if user authorized autonomy for scope:
    proceed; disclose assumptions; preserve reversibility
  elif decision_unknown AND materially_affects(data_semantics | point_in_time | evidence_validity |
    public_API/schema | migration | prod_rollout | irreversible_state | security | compliance |
    external_cost | user-visible_behavior):
    ask ONE concise question + recommendation + tradeoff → wait
  elif decision_known AND materially_affects(list above):
    confirm decision + disclose risk → wait
  elif reversible ∧ within_goal �� no risk:
    choose default; disclose assumption

materially_affects is minimum not safe-harbor. No multiple-choice questionnaires. Unavailable selector ≠ authorization.


REPORTING & AUDIT
-----------------
Subagent report MUST include: findings/changes, exact files/symbols, commands+results, uncertainty/risk, required primary action. Omit raw logs unless diagnostic.

A1 goal met + impl exists
A2 tests passed
A3 scope-change re-ran gate w/ visible record
A4 every M-trigger had tracks+owners
A5 each track produced substantial product used in result
A6 primary didn't duplicate/relabel
A7 targeted review not blind acceptance
A8 failures corrected before fallback
A9 no ownership conflict/regression
A10 assumptions/risks stated
A11 no in-scope work remains
A12 direct work names orchestration failure+attempts

Final response = one integrated result. Never transcript or stitched agent reports.
